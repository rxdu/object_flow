## What the author decided

All thirteen open questions were ruled on 2026-09-08, recorded as ADR-0065 to ADR-0072 and marked Accepted rather than pending; ADR-0073 followed and was confirmed the same day. The table in [`docs/design/declaration-syntax.md`](docs/design/declaration-syntax.md) §11 gives each answer and where it lives; §12 says what remains unestablished.

Five changed the language: a machine's creation guards bind any creation that replaces it, a cascade clause carries arguments, a third tracking mode for types that track no physical thing, a comparable type name on a reverse reference, and both state spellings in both places. Four refused a change: money keeps its currency in the declaration, evaluators stay verdict-only with a mirror for anything that assigns, confidentiality stays per object, and an authority list stays optional at a closed state. One closed a question already answered elsewhere. One kept a rule and changed what is reported. One deferred, and one agreed in principle without building it.

**Two answers moved because of evidence rather than argument.** Per-attribute confidentiality looked likely and turned out to have no need in the first consumer at all. The money counter turned out to rest on a mechanism that consumer was then thought not to use. *(Corrected 2026-09-24: it keeps a stock level for bulk accessories, D279.)*

## Challenges from the first consumer

Evidence from `~/RduWs/wr_inventory_management` that bore on accepted ADRs. Recorded 2026-09-07; all six resolved in design iteration 1 by ADR-0019 to ADR-0025 (accepted by the author 2026-09-28, ADR-0025 superseded except its core), with the worked rationale in [`docs/design/first-consumer-walkthrough.md`](docs/design/first-consumer-walkthrough.md) §4. Kept here as the record of what the evidence was.

1. [x] **Atomic outcomes across references, not only parts.** Completing a Delivery moves each reserved unit to `SOLD` and creates its warranty contracts in the same transaction (`wr:app/core/state_registry.py:761-770`, side effects `_update_delivery_items_to_sold`, `_create_delivery_warranties`). Units outlive deliveries, so by ADR-0003's test they are references, not parts. The model describes composite-to-part cascades only (ADR-0004), and ADR-0007, ADR-0012 and ADR-0013 together route cross-object consequences to consumers through at-least-once events. That leaves a window in which a Delivery is `DELIVERED` and its units are still `RESERVED` — an inconsistent state of exactly the kind the project exists to prevent. Options not yet weighed: a transition that declares outcomes on referenced objects, each gated normally and committed atomically; a multi-object transaction primitive; or accepting the window and making it explicit in the declaration. Affects ADR-0004, 0007, 0012, 0013. **Resolved by ADR-0019.**
2. [x] **Automatic transitions on the critical path.** The operations design's auto-fill: when a soft-pegged inbound unit reaches `AVAILABLE` at intake commit, its peg firms into `RESERVED` with no human step, specifically to close the double-booking window (`wr:docs/proposals/operations-system-design.md` §4 "Auto-fill on receipt", §5 step 5). Under ADR-0012 that becomes a consumer reacting to an event, which reopens the window. Whether this is a case of item 1 (an outcome declared on a referenced object) or a genuine trigger is the question. Affects ADR-0012. **Resolved by ADR-0019.**
3. [x] **Derived views are used deliberately.** Slot state (`UNFILLED` / `FILLED` / `FULFILLED`) is computed from foreign keys and the bound unit's status and is "NOT persisted as a column" (`wr:app/models/enums.py`, `SlotState`); the operations design's single-path rules say "demand is derived, not stored" (§9.0 rule 8). ADR-0004 rejects derived *lifecycle* state, and rightly — but slots have no transitions of their own; they are a projection over Delivery items and units. Resolve by wording in ADR-0004: derived state that has transitions is rejected; derived read-only views are the query surface's business. Reopen only if slots turn out to need transitions. Affects ADR-0004. **Resolved by ADR-0021.**
4. [x] **Concurrency is load-bearing and undocumented.** Double-booking was one of three motivating pains in the operations design (§1). The fix was a row lock on reservation and a `version` column on every entity with 409 on a stale write (`wr:docs/DESIGN.md` §2.6); the inventory ADR-0002 notes the TOCTOU hole a service-layer check leaves. ObjectFlow's DESIGN.md never mentions concurrency control. Tracked as an open model question above. **Resolved by ADR-0023.**
5. [x] **Time-driven transitions from day one.** `WarrantyContract` `ACTIVE → EXPIRED` on "contract expires" (`wr:docs/design/state-transition-system.md`); the alert catalogue lists low stock, procurement overdue, backorder aging, delivery date at risk, lease overdue and warranty expiring, all time-class (`wr:docs/proposals/operations-system-design.md` §6). ADR-0012 places these upstairs. The first consumer therefore needs a scheduler and the "inspectable but unexecuted timing metadata" answer at the same time as the core, not later. Affects ADR-0012. **Resolved by ADR-0022.**
6. [x] **Deletion is a second lifecycle mechanism.** Every entity has `is_deleted` (`wr:docs/DESIGN.md` §7.3); a cascade registry deletes children, and its pre-delete hooks call `force_transition`, which bypasses guards (`wr:docs/design/state-transition-system.md`, "Integration with Cascade System"; `wr:app/core/state_transition.py:577`). The inventory ADR-0003 found that soft-deleting one redundant customer row would have cancelled 102 deliveries, 43 services and 120 warranty contracts. ObjectFlow's docs never say what deletion is. A terminal transition gated on live references would have refused that cascade with remedy class `dependent`. Tracked as an open model question above. **Resolved by ADR-0024.**

## Data import

The port of the first consumer's production data is a designed path (ADR-0015, DESIGN.md "Data import"). Its properties were derived in discussion and are listed under Confirmations outstanding; the design work is here.

- [x] **Override path.** Decided by ADR-0040 and ADR-0054: a declared asserting transition for repair, gated on a capability with a mandatory reason and recording what it stepped over *(since ADR-0114 who may take it is the upper layer's; the mandatory reason stays)*; a built-in assertion for import and migration, so no type is unimportable by omission. *(Refined 2026-09-24 by ADR-0105: the built-in assertion is the import's alone; a migration is its own route.)*
- [x] **Validation report.** [`docs/design/publish-and-import.md`](docs/design/publish-and-import.md) §2 and §6, 2026-09-09. Three severities, and the per-class disposition is a committed file with four outcomes — undecided, clean upstream, admit, exclude — that an import refuses to run past while any class is undecided. An admitted violation becomes an admission the object carries, which `exceptions(type)` returns until the invariant holds again.
- [x] **Legacy history.** Every legacy entry is carried as a read-only entry of kind `legacy`, keeping its own object's fields, attached to the object and returned by `history` alongside ObjectFlow's own events; the record's silent stretches are declared and reported as gaps (DESIGN.md §11, ADR-0106).
- [x] **Soft-deleted rows.** Land in the type's declared deleted terminal state with provenance `asserted` (ADR-0024). Per-type naming of that state is import mapping work, not design.
- [x] **Legacy keys.** Preserved as `external: legacy` attributes with `lookup` by them (ADR-0018, ADR-0037).
- [x] **Files.** Content-addressed `file` attributes with the bytes in the deployment's blob store ([ADR-0017](docs/adr/0017-file-attachments-are-content-addressed-references.md), confirmed 2026-09-08). Legacy photos, packing-list PDFs and label templates port as controlled attributes written by the import's asserting transition. The blob store's own lifecycle expiry must be disabled.
- [x] **Cutover.** **Staged by object type**, decided by the author 2026-09-09, ADR-0075. Ownership is per type and absolute, so the order is forced: a type may migrate only after every type that references it has, and a cycle in the reference graph moves as one stage. A type held here and owned elsewhere is declared `mirror`.
