## Context

Earlier review rounds settled what a single request does. Three readers with no context of the design then read what the engine does beyond a request, each asked whether two careful builders following the text could build engines that differ: recording and correcting, publishing with a migration, the import, evaluators, erasure, proposals and flow changes, delivery, the acceptance harness, metrics, and the keys no reviewed example used. They found 97 findings, about 85 distinct, recorded as they wrote them in `cold-reading-review.md` §1 to §3. Most needed one sentence stating what the design implied; four changed what the engine promises, and the author decided those.

## Decision

1. **A publish leaves no object in an invariant violation nobody admitted.** It waits until every object that would violate an invariant after it, a new invariant over objects no mapping writes included, is fixed by its own transitions first, given a value by a backfill, a real one or a placeholder the author chooses, or admitted; a new invariant is evaluated over the objects as the mappings leave them. An admission is the preferred placeholder, and step 3 notices one on objects in a final state, which nothing could discharge.
2. **Erasure reaches everything that is the person's:** the whole group supersession joins, whichever member is named; every value that was personal under any version the object's history was written under, a publish newly marking one personal redacting it on objects already erased; and every object whose record it redacts, an input in a past event included, which gets an `erased` event.
3. **The engine asks an evaluator on every request and caches nothing.** `fresh` bounds the age of an answer by the as-of time the evaluator reports; with none declared the bound is zero, so only a live answer is used.
4. **A correction replaces the wrong value for the span it was held, explicitly.** The index of who held what reads the corrected value from when the wrong one was written; the original event is never changed; the correction's event names the attribute, the value replaced, the new value, the span, the reason and the actor; and every interval it relabels carries `.corrected_by`. It reaches only the value an attribute holds now.
5. **Recording:** `max_recording_delay` is `occurred within`; a correction takes the occurred time of what it corrects and is exempt from the bound; no invariant reads an observation collection, so a recording re-checks only its kind's invariants; `subject_open` reads the subject before the request; a correction's subject is the corrected observation's (review §5, 1 to 6).
6. **Publishing and migration:** "live" in publishing means every object; a migration is one transition per object carrying every mapping, in a stated order, objects in id order; constraints are added after the mappings; impacts have severities; a publish invalidates proposals it can no longer express and never rewrites their inputs; renames keep type and history; an object's `declaration_version` is its latest event's; spans a migration opens are marked (review §5, 7 to 22).
7. **The import:** one transaction per batch; a refresh that changes nothing writes nothing; the disposition file is an input and applies by class; a mirror's own declaration is what the import evaluates; personal values of an erased object are skipped; port-opened intervals carry the legacy changer or `unknown` (review §5, 23 to 33).
8. **Evaluators:** an absent argument makes no call; the guards of every reachable transition are consulted; `fresh` is a general duration, and an argument takes only a type and a description (review §5, 34, 35).
9. **Erasure:** it admits only an invariant it leaves violated; a group's erasures receive the request's inputs; `not_erased` refuses only a present value and never an erasure, and erasing again records what it retried (review §5, 36 to 38).
10. **Proposals and flow changes:** filing checks the transition, the object and the input types; the `DeclarationChange` lifecycle is printed whole; a refused approval is an attempt row and no event; a proposal may carry an expiry (review §5, 39 to 42).
11. **Delivery:** every event names a transition, `migrate`, `import` or `redact` among them; `pull` defaults to the acknowledged cursor, which may move back; lag is by recorded time (review §5, 43 to 45).
12. **The harness:** its reachability, survival, legacy-interval and erasure conditions are stated exactly (review §5, 46 to 49).
13. **Metrics:** the combined metric's broadcast is the model's; `.held` on a span is the value after its transition's writes, read by position; a gap is a window over an object that existed before its record; nothing accrues on a closed stretch; each aggregate reads its own present bodies; an unknown flag is reported unknown, and flags are evaluated on the declared groups; pieces are half-open and the window clips first; a percentile's rank is exact; `transition_count` counts the transition by name; a value is computed exactly and rounded once; buckets have stated forms (review §5, 50 to 67).
14. **The model's details:** coverage reaches every transition into a final state; uniqueness is partial over absence and spans a family; a `range` is an `int`; a bound name may not shadow a member; an abstract base declares no `summary`; `cascaded` is the exact sequence; the objects of a generated guard's refusal and of a nested aggregate are stated; and the order of a type's invariants is fixed (review §5, 68 to 78).

## Alternatives rejected

- **For decision 1:** a publish that leaves the violators unadmitted, which blocks their later writes, an erasure included, and fails the harness; checking only the objects a mapping writes, which makes the outcome depend on whether an unrelated backfill touches them; a placeholder value as the default, which satisfies a rule with a fake the record cannot tell from the truth, as ADR-0051 refused a sentinel for erasure.
- **For decision 2:** each member following only its own predecessors and successors, which leaves a merged duplicate's data behind; erasing only what is personal now; redacting a caller's event silently, which leaves its copies elsewhere unaware.
- **For decision 3:** the engine reusing a verdict for `fresh`, which lets a stale yes through what the other system changed, and makes two copies of the service answer differently.
- **For decision 4:** a correction as a change at its own time, which credits the wrong holder for the past permanently and treats an attribute's correction unlike an observation's (PRD D4).
- **For decisions 5 to 14:** the other reading each finding lists, in `cold-reading-review.md` §1 to §3.
