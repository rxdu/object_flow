# Audit a1: personal data end to end (P, and A where an identity is concerned)

Checkout 698034b, release binary `audit/bin/objectflow-service` (objectflow-core 0.2.0). Rubric: ADR-0204 §§1-5. All paths below are relative to the checkout `audit/repo` unless they start with `a1/`, which is `audit/a1/`, where every reproduction script and the stores it made are kept. Each script starts the binary with its pid in `a1/<name>.pid`, stops it by that pid, and is run as `cd a1 && python3 <script>`; `a1/of.py` is the shared helper (start, post, publish through `DeclarationChange`, count bytes in a store's files) and `a1/where.py <store> <needle>…` locates a needle in a store I made. No process of mine is left running (checked with `ps`; the remaining `objectflow-service` processes have their working directory in `a2`, `a3`, `a5`, `a6` or the repository).

## 1. How the area was enumerated, and why it is complete

**Where a personal value or a personal identity can be held.**
- *Every table of the schema*: the fixed tables in `core/crates/objectflow-core/src/store.rs:1562-1748` (`of_object`, `of_event`, `of_counter`, `of_subscription_position`, `of_attempt_rollup`, `of_attempt`, `of_declaration`, `of_legacy_entry`, `of_external_id`, `of_idempotency`, `of_admission`, `of_attribute_write`, `of_interval`, `of_sequence`, `of_engine_release`) and the indexes added at `store.rs:4588-4599`; each type's table, set tables and indexes as `table_parts` makes them (`store.rs:557-800`), the built-in types among them (`Proposal`, `label`, `DeclarationChange`, `Subscription`, `Operator`, observation kinds, `model.rs:1000-1060`, `1600-1660`, `1786-1975`). Every column that can take a value from a request, an effect, an import or a publish is a row below.
- *Every path that copies a value*: an effect's `assign`/`add`, a `create`/`call`/cascade input, a correction's record (`payload.corrected`), an assertion's or correction's `reason`, a guard's consulted key (evaluator arguments, metric bindings, `eval.rs:1600-1660`, `1829`), a proposal's stored inputs, a refused request's attempt row (`request.rs:5660-5770`), an admission (`request.rs:808`, `store.rs:4772`), an identifier's mint and a sequence's scope (`request.rs:4228-4330`, `store.rs:3388-3413`), an external identifier, a legacy entry (`import.rs:1060-1100`), a publish's record (`store.rs:3141`), the idempotency record (`request.rs:89-130`). The model's flags that decide what is personal were read from `model.rs:98-190` (`personal`, `identity`, `many`, `external`, `identifier.scope`, input `personal`) and the checker's check 10 (`check/names.rs:1600-2050`).
- *What the erasure does to each*: `request.rs:1585-1700` (the object, its spans, its events' inputs, the walk down and the callers), `request.rs:2157-2290` (`redact_others`), `request.rs:2461-2605` (proposals), `request.rs:3527-3690` (observations, the supersession chain), and the store's write of it, `store.rs:4795-4980` (redaction, the rename of an erased actor's identity, legacy entries, kept columns). The rename's reach is `Library::identity_held` (`model.rs:310-333`).
- *The files*: the store, its `-wal` and `-shm`, free pages and index free space (`store.rs:2004` `secure_delete`, `store.rs:2151-2230` the cut after an erasure), backups and restore (`docs/guides/operate.md:278-333`, `423-431`).
- *What leaves the process*: the stderr log (`core/crates/objectflow-service/src/main.rs:180-260`, `1100-1115`, `3512-3560`), `/metrics` and `/health`, and the evaluator call (`main.rs:215-260`).

**Every read.** The operations are those `docs/guides/wire-v1.json` lists (the brief's `core/crates/objectflow-service/tests/wire-v1.json` does not exist at 698034b): 21 under `/v1` and 4 sandbox controls, plus `GET /health` and `GET /metrics`. Each is graded below for what it answers after an erasure and for what it lets a reader infer, with every `export` source (`log`, an observation kind, `<Type>.intervals`, `.attempts`, `.transitions`, `.labels`, `.attempt_counts`, `core/crates/objectflow-core/src/export.rs:38-660`) and every part of a metric read (expression, dimensions, filter, `bind`, flags, `person_dimensions`).

**Why complete.** The storage rows cover every column of every table the store creates; the copy rows cover every step kind of `model.rs` `Step` and every writer of a JSON column; the read rows cover every operation of `wire-v1.json`. Each storage row was checked against the bytes of a store after an erasure (`a1/where.py` reads every column of every table of a store I made), so a place I did not think of would have shown up as an unexplained byte: in every run the remaining bytes were accounted for row by row.

**Left out, and why.** The reference runner and the Flow Studio (K and the gateway's areas); free text a flow does not mark `personal` (`context`, idempotency keys, an unmarked erasure reason, import dispositions' `reason`), which P does not cover as §3 states it; sandbox-only behaviour; PostgreSQL (not built); the cost of an erasure (area 4); the long-read `-wal` cut, which I could not make long enough to test on my small stores and which is held by named tests.

**Flows used.** `a1/hr.yaml`, `hr2.yaml`, `hr3.yaml`, `hr4.yaml`, `hr5.yaml`, `hr6.yaml`, `d682.yaml`, `d682b.yaml`, `adm.yaml`, `walk.yaml`, `mir.yaml`, and the shipped `docs/design/flow-format/examples/customers.yaml`. Every flow but `walk.yaml` was published on a deployment, so the core checker accepted it (`a1/t_publish.py chk <flow>`); `walk.yaml` the checker refuses only for its `Desk` lacking an erasure, which does not change the path tested. Variants for the checker are in `a1/v1.py` to `a1/v6.py`.
