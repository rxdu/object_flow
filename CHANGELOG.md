# Changelog

What each release of ObjectFlow's engine changed, for whoever runs it or builds on it. Releases follow semantic versioning (ADR-0180 decision 6), and from 1.0.0 the wire `/v1`, flow format 1 and the store's upgrade are held to ADR-0180's promise; a change that may refuse what an earlier release accepted is listed under its own heading. Each release is to be tagged `v<version>`, its service built from the tag with a SHA-256 checksum (`.github/workflows/release.yml`); none is tagged yet, 0.1.0 and 0.2.0 among them.

## Unreleased, toward 1.0.0

Release 1.0.0 is held until a production review, on the same 36.7k-object store as the first, finds no blocker or major (ADR-0183 decision 1; `docs/design/production-review.md`); each of the sixteen so far found some.

### Changes to what 0.2.0 answered

- The checker notices an optional attribute of an owned type that nothing writes, so it is always absent (`unwritten`, D557).
- The checker notices an assignment whose value can be absent through an optional it never tests, which refuses its request `value_in_range` (`absent`, ADR-0201 decision 7), other than a plain read moved into an optional attribute.
- Each event's payload records what it wrote, `wrote`: each attribute of its object it changed, with its value after and `null` where it cleared one, so a fold of an object's events reproduces its row, where only the inputs were recorded (D692, ADR-0209). An erasure redacts a personal value there as in the inputs, and `export` omits it. Events recorded before hold no `wrote`.
- A plain read of an absent value, a name or a path, assigned to an optional attribute clears it, as `clear` does, where 0.2.0 refused the request `value_in_range`; arithmetic on an absent value, and an absent value assigned to a required attribute, are still refused (ADR-0209 decision 5).
- The checker types a computed argument of a `call` or a `create`, refusing one of another kind than its input, an int passed to a time or an amount to an int, which the engine refused when run (the differential battery).
- The service refuses an option given where a value belongs, naming both (`--store takes a value, and is given the option --create`), where `--store --create --create` made a store file named `--create` and served it.
- A set input with a `null` element is refused `wrong_type`, where it reached the store and the service answered `500` naming the store's constraint; an import with one reports it as a class, `is not of its type` (the differential battery).
- A metric's `min`, `max` or `median` over dates is answered as a date, where it was the day's seconds as an integer, and a date less a date in a metric is a duration; the checker refuses a time or a date multiplied or divided in a metric's value, which the engine did not run or answered as seconds (the differential battery).
- The checker refuses a scalar written to a set attribute or a set to another, a state or a category written to an attribute, a division by a literal zero, a date moved by a literal part of a day, and an integer and a decimal literal written where the literal's places do not fit, each of which the engine refused when run (the differential battery). The Flow Studio's sandbox refuses such writes as the engine does, where it held them.
- An integer 0 times a duration or an amount is its zero, where the engine answered `not_run` (`i * du` with `i` 0, `m * 0`). The checker types a set of values, refusing one added, multiplied, ordered, negated or taken as a condition, and refuses an order over states, each of which the engine answered `not_run` (the differential battery). The Flow Studio's sandbox refuses a date moved by part of a day, writes a date's difference as a duration and an `if`'s literal 0 as the engine does.
- The checker refuses a member function called on what does not have it (`held` on an object, `entered_at` on a text), the intervals of a member its type does not track, and `entered_at` or `time_in` given a literal, each of which the engine answered `not_run` (the values audit's K-8).
- The checker types a metric's value: an aggregate over a text, a boolean, an enumeration's member, an identity or a state, a sum of times, and a sum or difference of a decimal and an integer or of two scales are refused at publish, where the engine answered `not_run` (the values audit's M2). A flow that published such a metric is refused; write `sum(o.w) + 1.00` for `sum(o.w) + 1`.
- The Flow Studio's sandbox writes a year below 1000 with four digits, reads a derived `this.intervals` or `this.transitions` as the engine's rows, writes a category by its name, and types an `if` by the branch it takes, where each failed or differed from the engine (the values audit's R7 to R9).
- The checker refuses `min` or `max` over an enumeration's members, which has no order and which the engine answered `not_run` (the values audit's R4); the Flow Studio's sandbox refuses a duration, a time, a decimal or an amount past what the engine holds, as the engine does (R5).
- The Flow Studio's sandbox rounds a quotient where the engine does, so a derived quotient that does not terminate is read, where it failed `500`, and a sum of a decimal and an integer reads as a decimal (the values audit's R1, R7).
- The checker refuses a loop over what is no collection, and an element added to or removed from a set that does not fit its elements' type, which the engine answered `not_run` or refused when run (the values audit's K-10).
- An import refuses a key a batch, an object, an `entered` time, a legacy entry or interval, a sequence's raise, or a disposition's class does not take, `400` naming it, a misspelt `sequence` having raised no sequence, where a misspelt key was read as absent and its value dropped without a word.
- The checker refuses a metric's value holding a comparison, a connective, `not`, `if`, `in`, a row's member outside an aggregate, a call of what is no aggregate, or an aggregate over the rows within another, which the engine answered `not_run` (the values audit's M2).
- The checker refuses an aggregate over what is no collection and over a literal whose elements share no type, and gives an element of a set of values its set's type, so `sum` over strings is refused; each was answered `not_run` (the values audit's K-10).
- The checker refuses a name or member that resolves to no value: an enumeration's name where a value goes, a name naming nothing, a type's member that is none of its states, a member of a plain value or of a state besides `category`, and a metric's own `count(where …)` outside a metric, each of which the engine answered `not_run` (the values audit's K-9).
- The checker types date and time arithmetic as §8.3 says, refusing a duration plus a date, a date mixed with a timestamp, and any product or quotient of a time or a date, which the engine answered `not_run` (the values audit's K-1, K-2).
- The checker refuses an enumeration ordered with `<`, `<=`, `>` or `>=`, a negative of what is no number, amount or duration, and membership in a single value, which the engine answered `not_run` (the values audit's K-4 to K-6).
- The checker refuses a call of a function the language does not have, such as `abs`, `round`, `coalesce` or `max(a, b)`, a function given other than one argument, and an unknown member function, each of which published and was answered `not_run` (the values audit's K-7, K-8).
- A step or argument that is exactly `actor.principal` skips its write where the request names no principal, as one that is exactly an unsupplied optional input does, where the request was refused `value_in_range` (D687).
- The checker types `actor.id`, `actor.kind` and `actor.principal`, so `"by " + actor.id` is refused at publish, where the engine answered `not_run` and the reference runner joined the strings; and it refuses a metric's `count` of an expression, which the engine answered `not_run` (D687).
- The checker refuses a `create`, or a `call` whose target names its type, into an `only via` transition from a transition the list does not name, which published and was refused when it ran (check 13's converse, the write path audit's R-05).
- The checker refuses a duration literal past 64 bits of seconds and an `int` divided by a `decimal`, which the engine answered `not_run`; a reader's filter holding such a duration is refused `malformed_filter` (ADR-0202 decision 8).
- A flow description holding a character outside YAML's printable set, such as U+FFFF or DEL, is refused at its line, where the engine's checker read it; and one whose escape makes a surrogate is refused by both checkers, where the reference checker crashed (the values audit's C2).
- An `int` literal past 64 bits is refused at publish (check 24), and a reader's filter holding one is refused `malformed_filter`, where it was read as a decimal (the values audit's L3).
- A collection is a set: `{1, 2} == {2, 1}` and `{2} == {2.0}` are true, `{1, 1}` holds one element, and `x in {a, b}` is `unknown` where `b` is unknown and `a` is not `x`, so `not (2 in {1, code})` no longer holds with `code` absent; a literal holding an unknown element is `unknown` elsewhere (the values audit's A8).
- The checker refuses `changed_since` given anything but an event, such as an int, which the engine read as a position in the log (the values audit's G7).
- The checker refuses `avg`, `median`, `percentile` and the time buckets `day` … `year` in an attribute's or an input's default, a `create`'s or a `call`'s inputs, a loop's `where` and a migration's backfill, as check 56 says ("outside a metric"), where it refused them only in a derived attribute, an invariant, a condition and an effect's `set`, `add` and `remove` (the values audit's G8). A flow that wrote one there no longer publishes.
- An input a create or a call passes into another object's personal attribute is personal on the caller's request too: `export` omits it from the caller's event, a refused attempt withholds it, and a request's digest masks it, where it was exported and kept in clear (caller taint, found probing the write path audit's last minor). What an erasure reaches through such an input is unchanged.
- A publish changing an attribute's type names, in its `type_changed` notice, each object holding a value it sets aside, and gives each a `migrate` event naming the change, where the notice said nothing was affected and the objects' histories said nothing (the audit's write path A-06).
- `declaration`'s and a publish report's `person_dimensions` mark a metric dimension reading an `identity` copied into an observation, as one on the type's own objects is, where it was left unmarked for the gateway (the audit's personal data R8).
- A part's `taken_by` that its whole's cascade breaks is refused with the remedy `delegable`, as through a call, where it said `unreachable_from_here`, telling an agent the request could never be done rather than to hand it to a person (the audit's write path A-04).
- A satisfied `check` names no `events`, and a creation's no `object_id`, each in the verdict's `not_computed`, where it named the positions and the id its simulation took, which the next real request was given for something else (the audit's write path A-05).
- The service sample's two examples that publish version 2 over version 1 moved to `service-migration.examples.yaml`, a file no change carries, since a publish step reads its files beside the examples file and a publish refused them `example_not_run`; `service.examples.yaml` now publishes with its module, as every shipped sample set does, which a deployment test holds (the guides' audit G-18).
- An event read by `history`, `events` or `pull` answers its `object_seq` and `source`, which it listed as not computed while `export` answered them (the guides' audit G-96). `/health` in a sandbox answers `writer_held_seconds` as `0.0`, as a deployment's fraction; a cursor sent as a number, and an operation asked by another method, are told what they take. A change drafted without its `source_ref` or `source` names it `missing`, not `malformed`. The guides' example identities are opaque, `u10442`, and the start's note on a log beside a restored copy says how to restore again.
- One object's rules reading its own transitions, attempts, declaration version or an observation collection read each by an index, never the whole log, attempt log or kind, and such a `get`, `availability` or `check` waits among the objects' reads; a `get` reads its object's last event alone for its version; a proposal's last verdict reads its approvals' attempts by index (the audit's cost B1, B11, B14; ADR-0205 decision 12).
- Metrics over attempts and attempt counts read their family's attempts by type, merged by key and stopped at the read's deadline, never the owner type or the whole attempt log; one over transitions reads the family's events by their index a page at a time (B3 to B5). `export` of an observation kind or a type's labels reads a page by an index on each record's last event, and `.attempt_counts` comes a day at a time to its limit and 8 MiB, where each read the whole log, or answered every day in one page (B12, B13).
- A read stops at its next step when its client goes, giving back its slot (D656, ADR-0205 decision 16); an urgent cut of the `-wal` bars every pool before waiting, and stops only the reads of a pool that did not drain in its moment (E4, decision 14).
- A store the service finds lost, its file or `-wal` replaced or removed, its file written over, or a read or a write meeting SQLite's words for a corrupt file, is served no more until a restart: every later read and write answers `503` `store_unreadable` or `store_replaced`, and the stop skips its checkpoint, where writes went on answering `200` into a log no start would read (ADR-0205 decision 8, D688).
- The `.intervals` export retracts a row a later commit deleted or moved, a correction merging it into the span before it or a version renaming or retyping its member, with a line `{"retracted": true, …}` at that commit's cursor, and gives each row its `entered_position`, so a consumer folding rows by their key holds what the store holds (ADR-0205 decision 9).
- A start binds its addresses before it touches the store, so one refused for a busy address changes no file; checks a store due an upgrade before the upgrade writes it; cuts back at its first look a log a killed process left, so an erasure's truncation due at the kill happens; says the restore's advice only beside a log holding frames; and a stop whose socket is gone stops all the same. `acknowledge` waits out another process's lock as a request does, and is refused `stale` past its retries, where it answered `500`. The start's note on a log beside a restored copy says how to restore again, where following it left the restore undone.
- A store started from a backup's copy, marked as `operate.md`'s backup commands now mark each copy, hands out no object number, event position, transaction or flow number the live store may have handed out after the copy: it advances each past the most it recorded in any period as long as the copy's age, doubled, says so at its start, and records the gap in `of_restore` (ADR-0207, the audit's durability B4). The store's release is 1.0.0; the upgrade from 0.2.0 adds `of_restore`, and restores a marked copy before it records its act. The backup commands open the store read-only, so a mistyped path is refused rather than copied empty.
- An erasure of an actor whose identity is personal replaces it in every copy, in any case of its letters (ADR-0205 decision 6): sets, a proposal's inputs and events, a refused request's attempt, a guard's consulted key, a correction's record and the approver of a version. A consulted argument of type `identity` is written `(personal)` there.
- An erasure records a `redact` event on each label whose note it removes, and on an object erased before whose history it redacts. A refused `publish` writes an attempt.
- Where an actor type marks its identity personal, a metric's rows name each actor by its object, never its identity.
- A dropped type keeps its erasure, and its objects stay readable after a restart, where they answered `500` (D690). An object a later erasure redacted no longer counts as erased itself (D691).
- A quotient written to a decimal is computed exactly and rounded once at the target's scale, half to even: `total / 3` with `total` 10.00 writes 3.3333 into a `decimal(12,4)`, where 0.2.0 wrote 3.3300 (ADR-0205 decision 1).
- A decimal literal combined with a wider decimal takes its scale, as `declaration-syntax.md` §8.1 says: `2.5 / w` with `w` 10.00 is 0.25, where it was 0.2.
- The body of `any`, `none` and `count` is a condition each element meets: `any(f in flags: f)` over `[false]` is false, where it was true, in both backends.
- Two decimals, and two rationals in a metric, compare exactly at any scale. Where they did not align within 128 bits, 0.2.0 compared them by sign alone, so `0.000…01 == 1000000000` held, and a metric compared them as floats.

### Changes that may refuse what 0.2.0 accepted

- `declaration` with no `type` is refused `400`, where it was read as a type with no name and answered `404`; `wire-v1.json` now records each operation's required keys, which a test sends each request without (the guides' audit G-93).
- A sandbox refuses `--busy-timeout`, which is a deployment's; its clock moved by `advance` and `set` at once; and an evaluator stubbed with an answer other than `satisfied`, `unsatisfied` or `unanswered`, in both backends (the guides' audit G-46).
- A metric's filter is refused `malformed_filter` past a query filter's bounds: more than 256 terms, aggregates nested more than two deep, a set of more than 1,000 members, or a metric called within it, where 0.2.0 ran it to the read's deadline (the audit's cost B6, ADR-0205 decision 15).
- `subscribe` is refused `invalid_input` where its filter selects nothing of the installed version or its durations make no sense: a `target_type` no type has by its exact name, a transition no selected type declares, a duration not positive, or a `dead_after` before its `lagging_after` (ADR-0205 decision 10, D689). A store due an upgrade that fails SQLite's quick check is refused at the start, where 0.2.0 upgraded it.
- A cursor in the gap a restore skipped is refused `invalid_cursor` by `pull`, `export` and `acknowledge`, where 0.2.0 honoured it once the log passed it and passed over the events written since (ADR-0207, the audit's durability B5); and an `.attempt_counts` cursor naming a day not over, or one a restore recounts, where 0.2.0 answered nothing until then (V5).
- A read that selects by a personal value is refused `personal` unless its body sets `"reads_personal": true`, whoever asks (ADR-0206). That covers:
  - a query's filter or order;
  - a `lookup` by a personal identifier;
  - `available`, `availability` and `check` decided by a guard or an invariant reading one;
  - a metric's filter and its binding of a dimension that names a person.

  0.2.0 answered a person's, a service's and the operator's, and refused only an agent's query, by its kind. Where an actor type marks its identity personal, every value of type `identity` counts. A request's refusal by a personal value names its holder only with the opt-in.
- An actor's identity is written only at its creation, refused `identity_unchanged` after it, and by both checkers at publish (ADR-0205 decision 5).
- A version adding a type whose ids would name an identity an actor holds is refused `identity_shadowed` (D669). An actor string naming both an object and another actor's identity names no actor.
- A key replays only the request it was first sent with: a different personal value is `key_reused`, and once an erasure removed what it sent, so is every request under it, a key 0.2.0 recorded included (ADR-0205 decision 3).
- `type` beside a proposal's or a change's id is held, refused `not_found` outside its family, and a proposal of either's transitions is refused `not_proposable`.
- More routes are refused:
  - `whole_open` refuses an effect moving a part, and a creation placing one, into a finished whole;
  - `not_erased` reads a step at any depth;
  - `only_via` holds through a call, a creation and a cascade;
  - an import is refused when its writes break an invariant of an object it does not place.
- Both checkers refuse:
  - a sequence scoped by a personal attribute;
  - an identifier format reading one;
  - a metric reading a value of type `identity` where actors' identities are personal;
  - a transition other than a creation or an erasure writing an actor's identity.
- An arithmetic past its type's bound is never unknown (ADR-0205 decision 2). That is an integer past 64 bits, a decimal or an amount past its digits, a date moved by part of a day, or a time past the calendar.
  - A guard, an invariant or a loop's filter reading one refuses the request `value_in_range`. An invariant held on one and admitted the write it should refuse, and a loop dropped the element.
  - A `get`, a `query` or a `metric` meeting one is refused `value_in_range`, naming the object and no value. A derived value was answered `null`, and a filter left the object out of its matches and of their negation.
  - A division by zero stays unknown, and only the side of an `and` or an `or` that does not decide refuses nothing.
- A value an effect, a default, a creation's argument or a backfill writes is held as its attribute's type holds it (ADR-0205 decision 1):
  - An integer written to a decimal is written at its scale. A store 0.2.0 wrote may hold `5` read as `0.05`, and the upgrade cannot tell those from values written so.
  - A decimal written to an integer is written only where it is whole. 0.2.0 stored `10.50` as `1050`.
  - A value of another type is refused `value_in_range`. 0.2.0 wrote it: an amount's currency relabelled, text into a number, and a date into a time column that left the object and its type's queries unreadable.
  - A backfill writing one refuses the publish.
- An `add` or a `remove` of an absent value is refused `value_in_range`, as a `set` of one is, where it answered `501 not run`.
- Both checkers refuse at publish, by the type their typing infers (ADR-0205 decision 1):
  - a write of a value of another type than its target's, such as a decimal computed into an int or an int into a string, where only a value whose kind was plain to see was checked;
  - a write that would round a decimal to fewer places unless it is a product or a quotient, as §8.3 says;
  - a number literal in a sum or a difference with more places than the decimal it is combined with;
  - an amount with more places than its currency's minor unit, or in a currency the engine has no minor unit for;
  - a duration literal that is no whole number of seconds;
  - a `count` whose body is no condition, `count(a in T: a.n)`, as `all`, `any` and `none` already were;
  - `time_in` naming no state, or `entered_at` neither a state nor a tracked member, in a derived attribute, an invariant, a uniqueness condition or a backfill, as check 58 already refused them in a transition's guards and effects.

  At run time a write that would round its decimal is refused `value_in_range`, and each literal and each such `time_in` is not run, where 0.2.0 rounded them or answered `0 s`.
- A metric over objects reaching a personal value through a reference or a derived attribute, `d.owner.name` or `d.owner_name`, is refused in both checkers, and a metric read's filter on a derived attribute reading one is refused `personal`; `pull` refuses a cursor past the log `invalid_cursor`, as `export` and `acknowledge` do (sixteenth production review, ADR-0203).
- An identity shaped as an object's id in any case of its letters, `Staff-2` as `staff-2`, is `malformed`, in both backends; a query by an actor the store does not know is refused `personal` where its filter or order reads a personal member, as an agent's is; a date moved by part of a day has no value, so an effect writing it is refused `value_in_range`, in both backends, where it answered `501 not_run`; a build of the engine from outside the repository stops unless `LIBSQLITE3_FLAGS` holds `-USQLITE_ENABLE_MEMORY_MANAGEMENT` (fifteenth production review, ADR-0202).
- A derived attribute whose reads go more than 64 deep, each reading the next, is refused `order` in both checkers, its first link past the depth named, and a read past it in a version installed before is `not_run`, where a chain of 9,500 that both checkers accepted answered all past the 65th as null; an agent's query whose `filter` or `order` reads a member marked personal is refused `personal`, as a metric's filter is; an assignment whose arithmetic has an absent operand refuses its request `value_in_range`, in both backends, where it answered `501 not_run`; an import's entry time for a dimension its type does not track is refused, where it was taken and dropped; a `--socket` path past 107 bytes is refused with the arguments, before `--create` makes a store (fourteenth production review, ADR-0201).
- A request naming a `type` beside its `object_id` is refused `not_found` where the object is of another family, and each write tool names the `request` it is sent as; `--max-connections` past 4,096 is refused at start; a publish preview's `expected_version` is an integer (thirteenth production review, ADR-0200).
- What an expression unfolds to counts the derived attributes of the modules it imports, so a doubling chain split across modules is refused by its first link past 10,000 reads; a request taking more than 64 transitions each caused by the one before is not run, where it overflowed the stack (twelfth production review, ADR-0199).
- An expression unfolding to more than 10,000 reads of derived attributes, each counted as often as it is made, as `d1: d0 + d0` on to `d13`, is refused `order` in both checkers before any later check reads its module; a decimal an effect writes past its digits refuses its request `value_in_range`, where it answered `501`; a dry run's checks past `--dry-run-timeout` answer it late, as its impact did (eleventh production review, ADR-0198).
- A derived attribute that reads itself through a reference, `parent.depth + 1` on a type whose `parent` is itself, is a cycle both checkers refuse, and an identifier's `{n:<width>}` is at most 20 digits; an agent's `submit` of another's draft is refused `publish_taken_by`, in both backends; `target_version` on any request but a proposal's `approve` is a `400` (tenth production review, ADR-0197).
- On a change another actor drafted, only an actor that may approve the next version may revise, reopen, refresh, withdraw or reject it, refused `invariant_violated`, `publish_taken_by`, `delegable`, in both backends, where an agent moved on a person's change; a request of a change's `publish` is `not_requestable`, naming `publish`, where it answered `501`; a query's `order` names at most 8 keys and its `fields` at most 256, each once, else `400`; an evaluator token holding a control character is refused at the start (ninth production review, ADR-0196 decisions 5, 7 and 9).
- Where no module declares `publishing.taken_by`, an agent's approval of the next version is refused `invariant_violated`, `publish_taken_by`, `delegable`, and any other kind's taken, in both backends, where the agent a version declared approved its own change; a request's `actor`, on every route that takes one, is an object of an `id` and a `principal`, else `400`, in both backends, where a read took one of any JSON type (eighth production review, ADR-0195 decisions 4 and 7).
- An identity holding a blank braille pattern, U+17B4 or U+17B5, a private-use character or a noncharacter is `malformed`; an import batch naming a kind of actor other than `human`, `agent`, `service` or `unknown`, or an actor past 64 KiB or breaking an identity's rules, is refused and writes nothing; a metric read keeping a dimension twice is a `400`; a query filter giving `and`, `or`, `implies` or `not` an operand that is no boolean is refused `malformed_filter`, where `title == "x" and title` answered an empty page (seventh production review, ADR-0194 decision 6).
- An identity is not empty, holds no whitespace at its ends nor any but a space within, no character that shows nothing, a variation selector, a combining grapheme joiner, a Hangul filler, a tag or a separator among them, and is not shaped as an object's id, `<type>-<number>`, else `malformed`; `identity_taken` compares identities without case; and an import may not admit `identity_taken`; in both backends, where each made another actor than the one it showed (ADR-0192 decision 6).
- `history` answers pages, at most `limit` events, 100 unless asked, with the `cursor` of the next, its legacy entries on the first, where one object's history answered 164.6 MB at once; `history` and `events` wait their turn in a pool of their own, `objects` (ADR-0192 decision 5, ADR-0195 decision 5).
- A query filter calling a metric, or holding more than 256 terms, is refused `malformed_filter`, where a metric per object and an `or` of 10,000 comparisons ran to the read's deadline (ADR-0192 decision 3).
- A proposal's `reject`, and its `withdraw` by any but its proposer, are held to the kinds of actor the proposed transition's `taken_by` names, refused as approving it would be, `invariant_violated`, `<transition>_taken_by`, `delegable`, in both backends, where an agent could reject what a person proposed (ADR-0191 decision 1).
- Money an effect writes past what an input holds, eighteen digits at its currency's minor unit, refuses its request `value_in_range`, in both backends, where an amount no request could send back was stored; a metric's `over` and a diagnostics' `window` are a positive duration, else `400`, where "-5 days" answered an empty page (ADR-0191 decision 3).
- An actor's identity names one actor: a creation or a write giving an identity another actor holds, of any type whose objects are actors, is refused `invariant_violated`, `identity_taken`, the holder named first, in both backends, where an agent issued a person's login was taken and the first made of the two answered for both; an identity holding a control, zero-width or bidirectional formatting character is `malformed`; and no module's invariant may be named `identity_taken` (ADR-0190 decision 4).
- A query filter nesting aggregates more than two deep, or writing a set of more than 1,000 members, is refused `malformed_filter`, where six nested aggregates ran past 30 s and a set of 10,000 values took 7.8 s, each holding a read's slot (ADR-0190 decision 3).
- A flow's source holding a bidirectional control or an invisible formatting character is refused, a `yaml` finding at its line, in both checkers, where a source could read otherwise than it shows (ADR-0190 decision 9).

- A correction may take `taken_by`, its own or its type's, where the checker refused it as writing more than it corrects, so a type's `taken_by: [human]` could not hold on a type with a correction and an agent rewrote a recorded bill, in both checkers (fifth production review NEW-CORRECTION, ADR-0190). A log whose reader has gone drops its lines, where `eprintln!` panicked on the broken pipe, losing answers to writes already committed and holding `/health` at `log_blocked` until a restart.
- A start refused for a store failing SQLite's quick check leaves the store's file and its `-wal` as they were: every connection the start opens before the store is served, the one reading the store's release and the check's, carries no log into the file as it closes, where a refused start wrote another state's `-wal` into a restored copy and emptied it (fourth production review). **Corrected:** the first fix, at `879fb2c`, covered the check's connection alone, and this entry, `integrate.md` §9 and the start's message claimed the copy untouched while the release's connection still wrote it, as the fifth production review measured (D609).
- A full disk answers a write `503 disk_full`, which a client may retry, where it answered `500`, and a fault of one code is written to the log at most once a second, the rest counted; every log line is stamped, the start's among them; a log no one reads holds one line and then drops lines, counted, so no request waits on it, where the service stopped at its next line; listening beyond loopback is said at the start; an evaluator's address is logged with its password hidden; what a run of short requests freed is given back once the service is idle (fourth production review).
- A publish report shows each of the checks' findings, where it kept the first of each code, so a second module's notice or a second refusal of one code was never shown (D608).

### Performance

- A metric over intervals that never reads `held`, the standard `time_in_state` among them, reads the state's spans and the member's by type, where it read each object's record whole and built each row's `held`: `time_in_state` idle on the two-year synthetic store from 782 ms to 374 ms, its answer the same.
- Requests that wait for the writer while it commits are committed together, each on a savepoint of one transaction and each answered only after its flush, so the writer is no longer one flush per request. Measured on the reference machine's two-year synthetic store, writes alone at twice the steady rate: 87 a second answered at p95 406 ms before, every one of 101 a second at p95 34 ms after (ADR-0208). `/metrics` counts the groups and the requests they held.
- A metric over more than 256 rows reads as a scan: a type its rows reach, by reference or as a member's other end, is read whole once instead of object by object, and a type they never reach is not read. Throughput, and any metric whose filter keeps only transitions that complete their object, reads only the events entering a finished state. Measured idle on a two-year synthetic store (12,000 claims) on a shared machine: the per-claimant reimbursement metrics from about 1.2 s to 0.45 s, the per-category one from 0.84 s to 0.35 s, throughput from 1.6 s to 0.14 s (`scripts/profile/idle.py`).
- Heavy reads at once each cost what one alone does: the bundled SQLite is built without `SQLITE_ENABLE_MEMORY_MANAGEMENT`, which put every connection's page cache behind one lock for the process, so four filters taking 2.2 s alone took 11.2 s each at once, and now 2.2 s each; the repository's `.cargo/config.toml` sets it for any build inside it, a build without it stops, a test fails a library without it, and the start's log says so (fourteenth production review M2, ADR-0201).
- A change's checks are linear in a type's transitions and in a chain of derived attributes, and a dry run's impact in the types a change adds: 8,000 transitions check in 0.57 s, where 70 s and an approval holding writes 71 s; 1,000 derived attributes in a chain, where 171 s; 1,000 added types dry-run in 2.2 s on a 37k-object store, where 14.5 s (tenth production review, ADR-0197 decision 5).
- A change's source parses, and its checks run, in time growing with what it holds, where a mapping's keys and a module's types each cost their square: a draft of 100,000 keys held every write 37.8 s and parses in 0.1 s, and a change of 8,000 types ran past eleven minutes in the dry run's slot and checks in 3.3 s (ninth production review N-4, N-8, N-10, ADR-0196 decision 1).
- A supersession group's erasure finds each member's predecessors by an index on their successor's column, which a store opened without it is given, where it read every superseding type whole for each member, 1.43 s for a group of 41 (ADR-0191 decision 5).
- An erasure reads the events it walks by the log's indexes, its object's own, those they caused and those that called them, where it read the whole log under the writer (fourth production review).
- `pull` and `export` read a page from their cursor by position, never the whole event log and every object: on six years of claims an empty pull takes 1 ms and 15 MB where 1.1 s and 462 MB, and twenty export pages of 1,000 1.4 s where 90.6 s and 1.9 GB; a subscription's lag reads its first pending event alone (fourth production review FEED).
- An external identifier is indexed whatever its marking, and a store opened without the index is given it: a go-live's import batch takes the same time at its last batch as its first, where 3,000 objects took 1.6 s at the start and 4.2 s at 36k objects (D606).
- After a publish, an import batch or any request of half a second or more, the service gives back to the system what it freed, which glibc kept: ten seconds after a publish it holds 25 MB on 37k objects where it held 975 MB, and 36 MB on 110k where 2.95 GB; `objectflow_memory_given_back_total` counts it (ADR-0187 decision 2).
- A query's page in creation order reads from its cursor, a chunk at a time, where each page read and filtered its type whole: a filter on a derived attribute read page by page over 12k claims took 1.6 s where 44.4 s, and its first page 0.03 s where 1.03 s (third production review READ-PAGES).
- A publish's dry run is linear in the store, where checking each object's optional identifiers swept every object without one: on 110k objects a publish adding one attribute submitted in 6.4 s where 41.5 s, and its approval held writes 9.1 s where 44.5 s (D605).
- A submit's dry run runs beside the writes, where every write waited for it: 83 s for a module of 3,000 types, which also checks ten times faster (D599, D600).
- A person's or an agent's submit of a version, which resolved its submitter by reading every actor for each object, took 6 s where it passed 20 minutes on 37k objects (D594); a per-person metric and a filter on a derived attribute 1 to 1.5 s where 77 to 83 s (D595); `available` reads only the objects its transition is taken from (D596); an erasure's truncation of the write-ahead log waits on no reader, where it made every write take 5 s while a read was open (D597).
- An attribute marked `indexed` has an index, which no release before made, and opening a store makes one it lacks: the go-live import of 36k objects took 36 s where 145 s (D593).
- Reads by index, not by reading a type whole: on a store of 36.7k objects a `get` took 1 ms where it took 184 ms, a 50-claim worklist 11 ms where 737 ms, a write about 10 ms where about 200 ms, and a publish adding one attribute 4 s of dry run and 5 s of approval where 214 s and 220 s held every write (production review PERF-SCAN, PUBLISH-FREEZE).

### Security

- A change's dry run holds no read of the store while its checks run, and its simulation stops at an urgent cut of the write-ahead log, where an erasure's values stayed in the store's files for as long as a dry run ran, 38.7 s for a check of a large change; the evaluator's transport follows no redirect, where a `302` from the configured endpoint sent a call to another host, whose answer decided a guard (eighth production review ERASE-WAL-DRYRUN and EV-REDIRECT, ADR-0195 decisions 1 and 3).
- The write-ahead log is cut back within 5 s of an erasure, and whenever it passes 64 MiB, new long reads held back while those running end: reads that always overlapped kept an erasure's values in it, and kept it growing, 3.2 GB in 150 s; on six years at 124 writes a second beside two six-second reads it now peaks at about 300 MiB (fourth production review).
- An idempotency key whose request an erasure redacted answers its first verdict whatever is sent under it, where it answered `409` to a wrong guess of the erased value and replayed the right one (fourth production review). A fault's reason is written to the log at most 1 KiB long, where a filter of 1.9 MB was written whole.
- A release's workflow refuses a tag whose commit's `check-all` has not passed, and runs the core's and the service's tests on the runner that builds the binary it ships (third production review).
- A store `--create` makes is `0600`, its `-wal` and `-shm` too; the service says at its start where a store's file is readable by others.
- An evaluator's failure is logged by its function, never its arguments or the endpoint's answer.
- An erasure leaves nothing it erased in the store's files (ADR-0181 decision 4).
